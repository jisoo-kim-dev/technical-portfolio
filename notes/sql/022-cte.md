# Lesson 22: CTE (WITH)

## What is a CTE?

A Common Table Expression, or CTE, is a temporary named result set created with `WITH`.

```sql
WITH CTEName AS (
    SELECT column_name
    FROM TableName
)
SELECT column_name
FROM CTEName;
```

The CTE exists only while the SQL statement is running. It does not permanently create or change a table.

## Why Use a CTE?

A CTE can divide a long query into clear steps.

It is useful when:

- a query contains multiple stages
- an intermediate result needs a meaningful name
- a nested subquery is difficult to read
- aggregation or joins should be separated from later filtering

## Basic Example

```sql
WITH CustomerAges AS (
    SELECT
        CustomerName,
        Age
    FROM Customers
)
SELECT
    CustomerName,
    Age
FROM CustomerAges;
```

`CustomerAges` contains the result of the query inside the parentheses.

The main query reads from that result as if it were a temporary table.

## CTE with Aggregation

```sql
WITH CountrySummary AS (
    SELECT
        Country,
        COUNT(*) AS CustomerCount
    FROM Customers
    GROUP BY Country
)
SELECT
    Country,
    CustomerCount
FROM CountrySummary
WHERE CustomerCount >= 2;
```

The CTE first counts customers by country. The main query then filters the summarized result.

## CTE with a JOIN

```sql
WITH CustomerOrders AS (
    SELECT
        c.CustomerName,
        o.Product,
        o.Amount
    FROM Customers AS c
    INNER JOIN Orders AS o
        ON c.CustomerID = o.CustomerID
)
SELECT
    CustomerName,
    Product,
    Amount
FROM CustomerOrders
WHERE Amount >= 100;
```

The CTE handles the join, and the main query filters the joined result.

## Multiple CTEs

Use one `WITH` keyword and separate multiple CTEs with commas.

```sql
WITH CustomerCountries AS (
    SELECT
        CustomerID,
        CustomerName,
        Country
    FROM Customers
),
OrderSummary AS (
    SELECT
        CustomerID,
        SUM(Amount) AS TotalAmount
    FROM Orders
    GROUP BY CustomerID
)
SELECT
    c.CustomerName,
    c.Country,
    o.TotalAmount
FROM CustomerCountries AS c
INNER JOIN OrderSummary AS o
    ON c.CustomerID = o.CustomerID;
```

A later CTE can also refer to a CTE defined before it.

## CTE vs Subquery

A subquery is written directly inside another query.

```sql
SELECT
    Country,
    CustomerCount
FROM (
    SELECT
        Country,
        COUNT(*) AS CustomerCount
    FROM Customers
    GROUP BY Country
) AS CountrySummary
WHERE CustomerCount >= 2;
```

The same logic with a CTE:

```sql
WITH CountrySummary AS (
    SELECT
        Country,
        COUNT(*) AS CustomerCount
    FROM Customers
    GROUP BY Country
)
SELECT
    Country,
    CustomerCount
FROM CountrySummary
WHERE CustomerCount >= 2;
```

Both can return the same result. A CTE is often easier to read when the query has several steps or when the intermediate result has a meaningful name.

## CTE vs Permanent Table

A CTE exists only for one SQL statement.

```sql
WITH CustomerAges AS (
    SELECT
        CustomerName,
        Age
    FROM Customers
)
SELECT *
FROM CustomerAges;
```

After the statement ends, `CustomerAges` no longer exists.

A permanent table remains in the database until it is changed or deleted.

## Column Aliases

Aliases created inside a CTE become column names available to the main query.

```sql
WITH OrderSummary AS (
    SELECT
        CustomerID,
        SUM(Amount) AS TotalAmount
    FROM Orders
    GROUP BY CustomerID
)
SELECT
    CustomerID,
    TotalAmount
FROM OrderSummary;
```

## Common Mistakes

### Forgetting the Main Query

Incorrect:

```sql
WITH CustomerAges AS (
    SELECT
        CustomerName,
        Age
    FROM Customers
);
```

Correct:

```sql
WITH CustomerAges AS (
    SELECT
        CustomerName,
        Age
    FROM Customers
)
SELECT *
FROM CustomerAges;
```

### Ending the Statement Too Early

Incorrect:

```sql
WITH CustomerAges AS (
    SELECT
        CustomerName,
        Age
    FROM Customers
);

SELECT *
FROM CustomerAges;
```

The semicolon ends the statement before the CTE is used.

### Forgetting a Comma Between CTEs

Incorrect:

```sql
WITH FirstCTE AS (
    SELECT CustomerID
    FROM Customers
)
SecondCTE AS (
    SELECT CustomerID
    FROM Orders
)
SELECT *
FROM FirstCTE;
```

Correct:

```sql
WITH FirstCTE AS (
    SELECT CustomerID
    FROM Customers
),
SecondCTE AS (
    SELECT CustomerID
    FROM Orders
)
SELECT *
FROM FirstCTE;
```

## Notes

- `WITH` begins a CTE.
- The CTE name is followed by `AS`.
- The CTE query is enclosed in parentheses.
- A main query must follow the CTE.
- The CTE exists for only one SQL statement.
- Multiple CTEs are separated with commas.
- A later CTE can reference an earlier CTE.
- Aliases created inside the CTE can be used by the main query.

## Key Takeaways

- A CTE is a temporary named query result.
- It can make multi-step SQL easier to read.
- A CTE can contain filtering, aggregation, or joins.
- The main query reads from the CTE like a temporary table.
- A CTE ends when the SQL statement ends.
